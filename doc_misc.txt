Daniel Struthers, 11:33PM (9/27)
More fun with Claude!  I have been working with it and there has been more good progress.  Code has be reorganized.  The IO basics are in place, you can use Ctrl-D, Ctrl-C, and Ctrl-\ signal end-of-input, kill current task, and task reset respectively.  Pressing Ctrl-C when in WOZMON (via hyforth bye) jumps back into hyforth.  Ctrl-\ effectively is like pressing the reset button.  The included hyforth has IO primitives open, read, write, close, and fg.  The forth shellcommand opens a second hyforth shell in another task.  You can task swith with Ctrl-] + n (where n is the task number you want to switch to).  hyforth's ps shows running processes.  The pipe | works in hyforth as an actual IO pipe like unix/dos so you can do things like words | wc . . . to do a word count of the forth words.  Ctrl-G now sends a bell to the terminal, but also plays a ding sound via the YM2151.  Forth's sndtest (after sndinit) now runs in the sound task since interacts with the sound chip via the /dev/snd device (runs in the background) and can be stopped with sndstop.  Serial was rewritten to properly support both Rockwell (default) and WDC 6551 chips.  SD cards mounted on the 6-pin SPI headers, can now be accessed through devices /dev/sd/0thru /dev/sd/7 depending on which header you use.  There is a lot more, but suffice to say that I am pretty happy with how much forward momentum can be made quickly.  IO is now buffered (128 byte read/stdin and write/stdout buffers) which made pipes run about 10 times as fast.  Lots of other stuff.

Daniel Struthers, 10/2/26 10:08PM
Latest: Three more versions have been pushed up (0.3-0.5) and there are lots of changes.  The cc65 stubs and headers are now available, but more importantly I have been working toward a more complete Plan9-like file namespace system.  There are not only the SPI disks (/dev//sd/N, and /sd/N; N being the SPI device number), but a RAM disk (/dev/sd/r/N and /ram; N here is the task number), a shared RAM disk (/dev/sd/s and /sram) and the paged ROM as one big disk (/dev/sd/x and /rom).  Now, the shared ROM is built by just dropping files in the rom build folder and they get built into the paged rom in the same place.  There are namespace commands, which include union to mount multiple namespaces into a single one (how Plan9 can join many folders into one bin folder for faster file lookups, etc.).  The important thing for all of the drives (SD cards, RAM disks, ROM disk) are all just accessed as HydraFS disks, so you can us all of the same commands (cp, ls, mv, rm, mkdir, etc.).  The ROM disk is, of course, read-only.  There is also now pipelining (|), redirection (> or >>), and spawn (&, run in a background task).  cat and echo work as expected, but are both hyforth words, not binaries.  Hyforth has had hex, decimal, and binary words added for output number formatting.  There is probably much, much more that I am forgetting.  Please play with the simulator.  It does everything the hardware does except output sound.  Maybe I'll make that happen soon!  There is a new test song, sndtest at the command prompt, that is supposed to test a lot of the YM2151 features now that ZSM-formatted song files are supported (Commander X16 supported format).  There is an MML-to-ZSM format converter somewhere in there as well.  Since I plan on getting the VERA video/sound/keyboard/mouse system driver running as well, it should be much easier to port software designed for the Commander X16 to Hydra.
